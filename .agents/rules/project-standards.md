# Стандарты проекта и правила разработки: Metallurgy R&D AI Assistant

Данный документ определяет строгие правила архитектуры, безопасности, лицензирования и стандартов кода. Правила обязательны к исполнению всеми разработчиками и AI-агентами.

---

## 1. Ключевые ограничения (Core Constraints — MUST NOT VIOLATE)

### Лицензионная чистота (K-13)
- Разрешены **ТОЛЬКО** пермиссивные лицензии: **Apache 2.0, MIT, BSD, PostgreSQL License, MPL-2.0**.
- **Строжайший запрет** на зависимости под лицензиями GPL, AGPL и их производными (включая MinIO, Neo4j Community GPL и др.).
- Для S3-хранилища используется **SeaweedFS** (Apache-2.0).
- Проверка лицензий зависимостей выполняется автоматически:
  ```bash
  uv run pip-licenses --fail-on="GPL;AGPL"
  ```

### Закрытый контур и автономность (Closed Contour & Offline Mode)
- Все внутренние сервисы разворачиваются в изолированной Docker-сети `internal_net` (`internal: true`).
- **Единственная точка выхода во внешнюю сеть** — прокси-сервис `egress-gateway` (Squid proxy на порту 3128), подключенный одновременно к `internal_net` и `egress_net`.
- Доступ разрешен только к доменам из белого списка (`services/egress-gateway/whitelist.txt`: OpenAlex, Semantic Scholar, Crossref, Unpaywall, CORE, J-Stage, Lens, ArXiv).
- Сервисы инференса (`llm-server` на порту 8080 для LLM, `ml-inference` на порту 8081 для эмбеддингов и реранкера) должны функционировать на 100% автономно с локально смонтированными весами моделей (`./models:/models:ro`). Веса предварительно загружаются через `scripts/download_models.py` и загружаются в память с `HF_HUB_OFFLINE=1` и `local_files_only=True`.

### Защита от галлюцинаций и фактологичность (ФТ-16)
- Ответы чата и доказательная база гипотез **ОБЯЗАНЫ** содержать прямые ссылки на точные идентификаторы фрагментов (`chunk_id`) из базы данных.
- Запрещается генерировать гипотезы или утверждения без привязки к конкретным чанкам проиндексированных статей (`chunks`).

## 2. Стек технологий и стандарты кода

### Окружение и язык
- **Python 3.12+**, строгая типизация (`requires-python = ">=3.12"`).
- Управление зависимостями исключительно через **`uv`** в рамках UV-монорепозитория (`tool.uv.workspace`). Использование `pip install` запрещено.
- Сборка пакетов: `hatchling`.

### Архитектура библиотек и сервисов
- `packages/common`:
  - База данных: PostgreSQL 16 с расширением `pgvector`, SQLAlchemy 2.0+ (asyncio), драйвер `asyncpg`.
  - Модели векторов: размерность 1024 (`Vector(1024)` для `Qwen3-Embedding-0.6B` с MRL-обрезкой и L2-нормализацией).
  - Миграции: Alembic.
  - S3-клиент: `aioboto3` для взаимодействия с SeaweedFS.
  - Схемы данных: Pydantic v2 (`pydantic>=2.10.0`).
  - Унифицированный клиент инференса: `common.inference` — `InferenceClient` (семафор фоновой нагрузки `llm_bg_max_concurrency` для SLA чата <= 30с, двухшаговый structured output при active thinking, экспоненциальные ретраи) и адаптеры LangChain (`QwenChatModel`, `QwenEmbeddings`).
- `packages/ingestion`:
  - Внешние коннекторы к научным базам данных (`httpx.AsyncClient` с `tenacity`).
  - Парсинг документов: HTTP-клиент к Docling (`pdf-parser:5001`).
- `services/api`:
  - Бэкенд: FastAPI (`fastapi>=0.115.6`), ASGI-сервер `uvicorn`.
- `services/orchestrator`:
  - Оркестрация графов: `langgraph>=0.2.60`, чекпоинты в БД через `langgraph-checkpoint-postgres>=2.0.10`.
- `services/ml-inference`:
  - FastAPI сервис локального инференса на порту 8081 (`transformers>=4.51.0`, `torch>=2.5.0`).
  - Эмбеддинги: `Qwen3-Embedding-0.6B` (`AutoModel`, `padding_side="left"`, last-token pooling, обрезка до 1024, L2-нормализация).
  - Реранкер: `Qwen3-Reranker-0.6B` (`AutoModelForCausalLM`, раздельная токенизация тела и суффикса `<think>\n\n</think>\n\n`, `softmax` логитов токенов `yes`/`no`, возврат `relevance_score`).
  - Динамический микро-батчинг (`BatchingQueueWorker`) через `asyncio.to_thread` и общий `asyncio.Lock` при `ML_INFERENCE_DEVICE=cuda`.
- `services/llm-server`:
  - Сервер `llama.cpp` (`ghcr.io/ggml-org/llama.cpp:server-cuda`) на порту 8080 для `Qwen3.8-27B` (GGUF) с флагами `--flash-attn on`, `--jinja`, `--reasoning-format deepseek`, `--no-context-shift`, `--cont-batching`.
- `services/egress-gateway`:
  - Контейнер Ubuntu Squid с проверкой белого списка (`dstdomain`).
- `eval`:
  - Метрики и оценка качества: `ragas>=0.2.10`, `scipy>=1.14.1`.

### Асинхронность и безопасность Event Loop
- Все операции ввода-вывода (БД, S3, внешние и мессервисные HTTP-запросы) выполняются строго асинхронно (`async`/`await`).
- **Категорически запрещено** блокировать event loop FastAPI синхронными вызовами PyTorch или длительными вычислениями.
- Тяжелые вычисления выносятся в отдельные потоки через `asyncio.to_thread` с явным ограничением параллелизма (семафоры/блокировки).
- Все HTTP-вызовы должны содержать таймауты и повторные попытки с экспоненциальным бэкоффом (`tenacity`).

### Конфигурация и переменные окружения
- Все параметры, адреса сервисов, имена моделей, размеры контекста и пороги определяются через `pydantic-settings` (`Settings` на базе `BaseSettings`).
- **Запрещены** хардкод URL, имен моделей и секретов в коде.
- Файл `.env.example` является эталоном конфигурации. При добавлении новых переменных окружения обязательно обновлять `.env.example`.

### Линтинг, форматирование и тесты
- **Ruff**: `line-length = 100`, `target-version = "py312"`.
  - Игнорируемые правила: `B008` (вызовы в дефолтных аргументах функций — необходимо для FastAPI `Depends`), `BLE001` (перехват общих исключений), `F841` (неиспользуемые переменные).
- **Pytest**: `asyncio_mode = "auto"`, `asyncio_default_fixture_loop_scope = "function"`, директории тестов: `["services", "packages", "eval"]`.
- Все публичные функции и методы обязаны иметь аннотации типов для успешного прохождения `mypy`.
- Для каждой новой функции или изменения спецификации обязательны интеграционные или модульные тесты в директориях `tests/`.

### Стандарты Docker
- Multi-stage сборка: этап `builder` с кэшированием `uv` (`--mount=type=cache,target=/root/.cache/uv`), легковесный образ `runtime` на `python:3.12-slim-bookworm`.
- Безопасность: выполнение только от непривилегированного пользователя (`appuser`).
- Изоляция сети: только внутренняя сеть `internal_net` для всех сервисов приложения.

## 3. Протокол Spec-Driven Development (SDD)

1. **Спецификация прежде кода:** Запрещается писать реализацию новых модулей или вносить критические изменения до создания спецификации в `openspec/changes/<change-name>/` и её утверждения пользователем.
2. **Трассируемость требований:** Каждая задача реализации обязана явно ссылаться на идентификаторы требований из спецификации (например, `INF-1`, `ФТ-14`, `К-7`).
3. **Контроль качества перед сдачей задачи:**
   - Запуск тестов: `uv run pytest`
   - Проверка линтером: `uv run ruff check .`
   - Проверка типов: `uv run mypy packages services`
   - Проверка лицензий: `uv run pip-licenses --fail-on="GPL;AGPL"`
   - Отчет агента должен содержать точный вердикт выполнения этих проверок.

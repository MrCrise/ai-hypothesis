# Spec Delta

## Purpose
Превращение научных статей и внутренних документов (PDF, DOCX) в структурированный документ и набор чанков,
пригодных для индексации и цитирования по `chunk_id` (ФТ-11, ФТ-13, ФТ-16).

## ADDED Requirements

### Requirement: Структурированный результат разбора
Система MUST возвращать для каждого успешно разобранного документа структуру, содержащую: заголовок документа
(если найден), упорядоченный список разделов с заголовком и уровнем, текстовые блоки с номером страницы и
принадлежностью к разделу, таблицы с ячейками (строка, столбец, текст) и подписью, подписи рисунков и
список литературы. Колонтитулы страниц MUST NOT попадать в текстовые блоки.

#### Scenario: Статья с таблицей химсостава
- **WHEN** разбирается PDF статьи с таблицей «Table 4. Chemical compositions of steels in wt%.»
- **THEN** в результате есть таблица с этой подписью, номером страницы и ячейками, где значение «0.41» стоит
  в строке «4340» и столбце «C»

#### Scenario: Колонтитулы отброшены
- **WHEN** на каждой странице PDF есть колонтитул с названием журнала
- **THEN** этот текст отсутствует среди текстовых блоков результата

### Requirement: Список литературы
Система MUST выделять пункты списка литературы в отдельное поле результата, сохраняя их порядок и исходный текст,
и MUST NOT включать их в текстовые блоки разделов.

#### Scenario: Раздел References
- **WHEN** в документе есть раздел с заголовком «References» (или «Literature», «Bibliography») из пунктов списка
- **THEN** каждый пункт попадает в список литературы в исходном порядке, а не в текстовые блоки

### Requirement: OCR только для страниц без текстового слоя
Система MUST запрашивать OCR при разборе PDF, только если хотя бы одна страница не содержит текстового слоя
(меньше настраиваемого порога символов). Если текстовый слой есть на всех страницах, OCR MUST NOT
использоваться. Факт применения OCR MUST фиксироваться в метаданных результата.

#### Scenario: Скан с готовым текстовым слоем
- **WHEN** разбирается PDF-скан, у которого на всех страницах есть текстовый слой
- **THEN** разбор выполняется без OCR, и в метаданных отмечено, что OCR не применялся

#### Scenario: Страница без текста
- **WHEN** в PDF есть страница без текстового слоя
- **THEN** разбор выполняется с OCR, и в метаданных отмечено, что OCR применялся

### Requirement: Поддержка DOCX
Система MUST разбирать документы DOCX в ту же структуру результата, что и PDF. Для DOCX номер страницы MAY
отсутствовать.

#### Scenario: Внутренний отчёт в DOCX
- **WHEN** загружается DOCX с заголовками разделов, абзацами и таблицей
- **THEN** результат содержит эти разделы, абзацы и таблицу с ячейками

### Requirement: Нарезка на чанки
Система MUST преобразовывать результат разбора в чанки, у каждого из которых есть текст, название раздела и номер
страницы (если известен). Текст раздела MUST нарезаться по границам блоков с ограничением длины чанка из настроек;
чанк MUST NOT пересекать границу раздела. Каждая таблица MUST становиться отдельным чанком, содержащим её
подпись и содержимое. Список литературы MUST NOT нарезаться в чанки.

#### Scenario: Таблица отдельным чанком
- **WHEN** в разделе «2. Experimental» есть абзацы и таблица с подписью «Table 1. Experimental conditions.»
- **THEN** таблица образует отдельный чанк, начинающийся с подписи, а абзацы — чанки этого же раздела

#### Scenario: Длинный раздел
- **WHEN** суммарная длина абзацев раздела превышает лимит длины чанка
- **THEN** раздел делится на несколько чанков, ни один не длиннее лимита, кроме случая одного абзаца длиннее лимита

### Requirement: Ошибки и устойчивость сервиса разбора
Система MUST применять таймауты и повторные попытки с экспоненциальной задержкой к обращениям в сервис разбора.
Если сервис вернул статус `failure` или превышено время ожидания, система MUST выдать ошибку разбора
с именем файла и причиной, а не пустой результат. Неподдерживаемый формат файла MUST отклоняться до обращения
к сервису.

#### Scenario: Сервис вернул failure
- **WHEN** docling-serve завершил задачу со статусом `failure`
- **THEN** вызывается ошибка разбора с именем файла и текстом ошибок сервиса

#### Scenario: Неподдерживаемый формат
- **WHEN** передан файл с расширением `.exe`
- **THEN** вызывается ошибка неподдерживаемого формата без обращения к сервису

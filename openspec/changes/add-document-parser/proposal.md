# Proposal: разбор документов корпуса (GEN-7)

## Why

ФТ-11 требует разбирать PDF статей с сохранением разделов, таблиц (химсостав, режимы), подписей к рисункам
и списка литературы, а ФТ-13 — принимать внутренние PDF/DOCX заказчика. Сейчас в `ingestion/parser` есть только
заглушка, которая отправляет файл в устаревший эндпоинт `docling-serve` (`/v1alpha/convert/file`) и возвращает сырой JSON.
Без структурированного результата нельзя построить индекс (`chunks`) и выполнить ФТ-16 (ответы со ссылкой на `chunk_id`).

Инструмент выбран бенчмарком на 24 открытых статьях золотого датасета (GEN-5): Docling без OCR при наличии
текстового слоя — 55/55 контрольных цитат, 47/47 таблиц с подписью, 99,2 % чисел ячеек совпадают с PDF;
с OCR по умолчанию RapidOCR портит текстовый слой сканов ISIJ (76,3 %). GROBID не нужен: литература
у Docling на уровне Crossref (582 против 574).

## What Changes

- Новая Pydantic-схема результата разбора: разделы, текстовые блоки со страницей, таблицы с ячейками и подписью,
  подписи рисунков, список литературы, метаданные разбора.
- Клиент `docling-serve` на API `v1` (асинхронный режим с опросом статуса, таймауты и повторы через `tenacity`).
- Решение об OCR на стороне клиента: OCR включается только если в PDF есть страницы без текстового слоя.
- Разбор DOCX тем же сервисом (ФТ-13).
- Нарезка результата в чанки для таблицы `chunks`: текст по разделам с ограничением длины, каждая таблица —
  отдельный чанк вместе с подписью, у каждого чанка номер страницы.
- `docker-compose.yml`: образ `docling-serve` закреплён на `v1.38.2` вместо `latest`.
- Новые параметры в `Settings` и `.env.example` (таймаут, интервал опроса, порог символов на страницу, длина чанка).
- **BREAKING** (внутренний): `parse_pdf_bytes(...) -> dict` заменяется на `parse_document(...) -> ParsedDocument`.
  Других вызовов функции в репозитории нет.

## Impact

- Код: `packages/ingestion/src/ingestion/parser/`, `packages/common/src/common/schemas/` (новая схема),
  `packages/common/src/common/config.py`, `.env.example`, `docker-compose.yml`.
- Зависимости `ingestion`: `docling-core` (MIT) — типизированная модель ответа docling-serve; `pypdfium2`
  (BSD-3/Apache-2.0) — проверка текстового слоя. GPL/AGPL не добавляются.
- Лицензии весов в образе docling-serve: Apache-2.0 и CDLA-Permissive-2.0 (`docling-models`). Второй нет
  в списке К-13 — нужно подтверждение заказчика.
- Схема БД (`ChunkModel`, `PaperModel.parsed_structure`) не меняется. Вычисление эмбеддингов и запись в БД
  (`indexer`) — вне этого изменения.

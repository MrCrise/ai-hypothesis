# Design

## Context

- `docling-serve` уже стоит в `docker-compose.yml` (профиль `ml`, сеть `internal_net` без выхода наружу).
  Модели layout/tableformer/OCR вшиты в образ (`docling-tools models download` в Containerfile, `DOCLING_SERVE_ARTIFACTS_PATH`),
  поэтому сервис работает автономно.
- API `/v1alpha/*`, на который смотрит текущая заглушка, в docling-serve 1.38+ заменён на `/v1/*`.
- Ответ сервиса с `to_formats=json` — сериализованный `DoclingDocument` (`document.json_content`).
- Мотивация и выбор инструмента — см. proposal.md (бенчмарк GEN-7).

## Goals / Non-Goals

**Goals:**
- Типизированный результат разбора, не зависящий от формата Docling (смена парсера не трогает потребителей).
- Детерминированная нарезка, которую можно проверить на контрольных цитатах золотого датасета.

**Non-Goals:**
- Вычисление эмбеддингов, запись в `chunks`/`papers` и загрузка в S3 (`indexer`, другие задачи).
- Нормализация чисел и единиц в таблицах, разбор формул, распознавание отдельных ссылок на поля (авторы/год).
- Понижение уровня заголовков по нумерации: используется плоский уровень Docling (`do_pdf_heading_hierarchy` выключен).

## Decisions

1. **Адаптер на `docling-core`, а не разбор сырого JSON.** `DoclingDocument.model_validate(json_content)` даёт
   типизированный обход в порядке чтения (`iterate_items`), подписи (`caption_text`) и ячейки таблиц.
   Альтернатива — свой разбор словаря — ломается при смене версии схемы. `docling-core` (MIT) лёгкий,
   без torch; версия совместима с той, что внутри образа (`>=2.103`).
2. **Своя схема `ParsedDocument` в `common.schemas.parsed`.** Потребители (indexer, оркестратор, отчёты) не видят
   типов Docling. Схема сохраняется в `PaperModel.parsed_structure` через `model_dump(mode="json")`.
3. **OCR решается на клиенте по текстовому слою.** `pypdfium2` считает символы на каждой странице; если хоть одна
   страница ниже порога `parser_min_chars_per_page` — запрос с `do_ocr=true`, иначе `do_ocr=false`.
   Альтернативы: `do_ocr=true` всегда (портит сканы ISIJ, см. бенчмарк); `force_ocr` (ещё хуже для готового слоя);
   OCR по отдельным страницам (docling-serve так не умеет, пришлось бы резать PDF). Проверка выполняется в
   `asyncio.to_thread`, чтобы не блокировать event loop.
4. **Асинхронный API с опросом.** `POST /v1/convert/file/async` → `GET /v1/status/poll/{task_id}` → `GET /v1/result/{task_id}`.
   Длинные статьи (20+ страниц, OCR) не упираются в таймаут одного HTTP-запроса. Каждый HTTP-вызов — с таймаутом
   и повторами `tenacity` (сетевые ошибки и 5xx); общий дедлайн задачи — `parser_task_timeout`.
5. **Литература — по заголовку раздела.** Docling не даёт ссылкам отдельной метки: это `list_item`/`text` после
   заголовка, совпадающего с `referen|literature|bibliograph|литератур|источник`. Всё после такого заголовка до
   следующего заголовка идёт в `references`.
6. **Нарезка: таблица — отдельный чанк.** Текст раздела набирается блоками до `chunk_max_chars`; чанк получает
   страницу первого блока. Таблица → чанк «подпись + markdown-таблица», чтобы числовые ответы находились
   поиском вместе с контекстом подписи. Подписи рисунков идут в текст раздела как обычные блоки.
7. **Образ закреплён на `v1.38.2`** (27.10.2026), а не на свежем `v1.40.0`: версия старше двух недель.

## Risks / Trade-offs

- [Бенчмарк гонялся на docling 2.153 (как в docling-serve 1.40), образ 1.38.2 содержит более ранний docling] →
  прогнать контрольные цитаты через запущенный образ при первом `docker compose --profile ml up`.
- [Страница-скан без текстового слоя включает OCR для всего документа, и OCR может испортить остальные страницы]
  → флаг `ocr_applied` в метаданных; такие документы видно и их можно проверить вручную.
- [Неанглийские заголовки литературы не распознаются] → паттерн расширяем через настройки; русский вариант добавлен сразу.
- [Таблица, не влезшая в лимит декодирования TableFormer, приходит одной ячейкой] → чанк всё равно создаётся,
  текст не теряется.
- [Лицензия CDLA-Permissive-2.0 у весов docling-models вне списка К-13] → вопрос заказчику, до ответа — как есть.

## Migration Plan

Заглушка `parse_pdf_bytes` нигде не вызывается — удаляется без миграции. Откат — revert коммита; схема БД не меняется.
